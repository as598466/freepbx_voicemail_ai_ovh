Voicemail AI : fonctionnement technique

Ce qui se passe entre le moment où un correspondant raccroche après avoir laissé un message et celui où le destinataire reçoit un e-mail avec la transcription et l'enregistrement.

Déclenchement Pipeline Replis Transcription Audio E-mail produit Configuration Journaux Fichiers
Invariant central : un message vocal n'est jamais perdu. Chaque chemin d'échec se termine par la livraison de quelque chose : l'e-mail enrichi, un e-mail dégradé, ou à défaut l'e-mail d'origine d'Asterisk transmis tel quel à sendmail, exactement comme la commande par défaut.

1. Déclenchement par FreePBX

FreePBX écrit le champ Mail Command (Voicemail Admin → Settings) dans /etc/asterisk/voicemail.conf sous la clé mailcmd, qui vaut /usr/sbin/sendmail -t par défaut. Le projet la remplace :

mailcmd=/usr/bin/php /opt/freepbx-voicemail-ai/bin/voicemail-ai

Quand un message est déposé dans une boîte configurée avec un e-mail, app_voicemail génère l'e-mail de notification complet (en-têtes RFC 5322, corps texte issu du gabarit FreePBX, pièce jointe audio si Email Attachment = yes) dans un fichier temporaire, puis lance :

( mailcmd < fichier ; rm -f fichier ) &
Appel terminéLe message est enregistré dans la boîte vocale.
app_voicemailConstruit l'e-mail MIME avec le WAV en pièce jointe.
Shell en arrière-planEnvoie le fichier sur stdin de la commande, puis le supprime.
bin/voicemail-aiProcessus PHP lancé sous l'utilisateur asterisk.
  • Asynchrone : la commande tourne en arrière-plan, la durée de la transcription (plusieurs secondes, voire minutes en cas de nouvelles tentatives) ne bloque jamais l'appel ni Asterisk.
  • Code de sortie ignoré : Asterisk n'exploite pas le code de retour. Le script renvoie 0 si quelque chose a été livré, 1 sinon, mais seule la livraison compte ; les incidents sont tracés dans syslog.
  • Pas de terminal : stdout et stderr ne sont lus par personne en production. Les journaux passent par syslog (ident voicemail-ai, facility mail).
  • Droits : le processus hérite de l'utilisateur asterisk, d'où config/config.php en root:asterisk 640 (il contient le jeton d'API).

2. Déroulement de l'exécution

La colonne de gauche est le chemin nominal ; celle de droite indique ce qui se passe si l'étape échoue.

Chemin nominal
En cas d'échec
1Lecture de stdin bin/voicemail-ai

L'e-mail complet est lu en mémoire avant de charger quoi que ce soit, pour qu'il reste disponible quoi qu'il arrive ensuite.

2Filet de sécurité de dernier recours register_shutdown_function()

Une fonction d'arrêt est enregistrée ; elle ne s'active que si le script s'arrête sans avoir terminé normalement.

Transmis tel quel

Erreur fatale (vendor/ absent, erreur de syntaxe, mémoire épuisée…) : l'e-mail brut part vers /usr/sbin/sendmail -t -oi via proc_open, sans aucune classe du projet.

3Autoloader et options Cli::main()

Chargement de Composer, lecture de --config=, --dry-run, --verbose. Les warnings PHP sont convertis en ErrorException pour qu'aucun échec ne passe inaperçu.

Ignoré

Option inconnue (faute de frappe dans Mail Command) : avertissement sur stderr et syslog, l'exécution continue.

4Configuration Config::fromFile()

config/config.php (ou $VOICEMAIL_AI_CONFIG) est chargé dans un objet valeur en lecture seule, avec les valeurs par défaut.

Transmis tel quel

Fichier absent, illisible ou invalide : Cli::rescue() transmet l'e-mail brut à /usr/sbin/sendmail (chemin par défaut, sans lire la config).

5Construction des dépendances SyslogLogger · Application::create()

Journal syslog, puis parseur, transcripteur OVH, convertisseur ffmpeg, composeur PHPMailer et transmetteur brut. Seul endroit où la config est lue.

Transmis tel quel

Toute exception imprévue qui sort d'Application est rattrapée par Cli::rescue(), qui utilise cette fois le sendmail configuré.

6Analyse de l'e-mail VoicemailParser::parse()

Extraction de From, To, Subject, Date, Message-ID, X-Asterisk-CallerID, X-Asterisk-CallerIDName, du corps texte FreePBX et de la première pièce jointe audio (audio/* ou extension wav, gsm, mp3…).

Transmis tel quel

E-mail illisible, ou aucune pièce jointe audio (e-mail « pager », boîte en attach=no) : RawMailForwarder l'envoie via sendmail -t -oi.

7Transcription OvhTranscriber::transcribe()

Le WAV d'origine est envoyé à OVHcloud AI Endpoints (Whisper). Nouvelles tentatives sur erreur réseau, 408, 425, 429 et 5xx.

Dégradé

Échec définitif : $transcript = null. L'e-mail enrichi part quand même, avec un avertissement, l'en-tête X-Voicemail-Transcription: failed et l'audio joint même si attach_audio vaut false.

8Conversion en MP3 AudioConverter::toMp3()

Uniquement si l'audio doit être joint. ffmpeg produit un MP3 mono 16 kHz, beaucoup plus léger que le WAV.

Dégradé

ffmpeg absent, non exécutable, en erreur, ou audio.ffmpeg = null : le WAV d'origine est joint à la place.

9Composition de l'e-mail VoicemailMailer::compose() · TemplateRenderer

PHPMailer assemble les versions HTML et texte (gabarits templates/email.*.php), les en-têtes repris d'Asterisk et la pièce jointe.

Transmis tel quel

Pas d'expéditeur ni de destinataire, gabarit en erreur, exception PHPMailer : l'e-mail brut est transmis.

10Envoi PHPMailer → /usr/sbin/sendmail (Postfix)

Postfix prend le message en charge et le délivre. En --dry-run, le MIME est écrit sur stdout à la place.

Transmis tel quel

Échec de sendmail lors de l'envoi enrichi : nouvelle tentative avec l'e-mail brut. Si celle-ci échoue aussi, journal CRIT « voicemail notification lost ».

✓Journalisation et sortie exit 0

Une ligne de synthèse : appelant, destinataires, statut de transcription. Asterisk supprime ensuite le fichier temporaire.

4. Transcription (OVHcloud AI Endpoints)

API compatible OpenAI, appelée en cURL avec un formulaire multipart/form-data :

POST https://oai.endpoints.kepler.ai.cloud.ovh.net/v1/audio/transcriptions
Authorization: Bearer <ovh.token>
Accept: application/json

file             = <WAV d'origine>
model            = whisper-large-v3
response_format  = verbose_json
temperature      = 0.0
language         = fr          (si configuré)
prompt           = …           (si configuré)

La réponse JSON fournit text (obligatoire), language et duration. Le texte est nettoyé des espaces en début et fin.

Nouvelles tentatives

  • Retentées : erreur réseau/cURL, HTTP 408, 425, 429, 500, 502, 503, 504.
  • Non retentées : 4xx (jeton invalide, fichier refusé…), JSON invalide ou sans text.
  • Attente exponentielle : 1 s, 2 s, 4 s… jusqu'à max_retries (2 par défaut, soit 3 essais).

Délais

  • Connexion : 15 s maximum.
  • Requête complète : ovh.timeout (120 s par défaut).
  • Pire cas avec les valeurs par défaut : environ 3 × 120 s + 3 s d'attente, soit un peu plus de 6 minutes avant le repli. Sans conséquence pour l'appel, puisque tout se passe en arrière-plan.
Pourquoi le WAV et pas le MP3 ? Le MP3 est compressé et rééchantillonné pour réduire la taille de la pièce jointe. Whisper obtient de meilleurs résultats sur l'enregistrement d'origine, sans perte supplémentaire. Sans jeton, l'accès anonyme est limité (10 Mo / 60 s d'audio).

5. Conversion audio

Le WAV est écrit dans un fichier temporaire (/tmp/vmai-*), converti, puis les deux fichiers sont supprimés dans tous les cas. Commande lancée sans shell, via ProcessRunner (proc_open avec un tableau d'arguments) :

ffmpeg -hide_banner -nostdin -loglevel error -y \
       -i /tmp/vmai-XXXX \
       -ac 1 -ar 16000 -c:a libmp3lame -b:a 32k \
       /tmp/vmai-XXXX.mp3

Mono, 16 kHz (MPEG-2, lisible partout, contrairement au 8 kHz), 32 kbit/s : largement suffisant pour de l'audio téléphonique. Le fichier joint garde le nom d'origine avec l'extension .mp3.

6. E-mail produit

Structure MIME

  • multipart/mixed
    • multipart/alternative
      • text/plainemail.txt.php
      • text/htmlemail.html.php
    • audio/mpegbase64, si l'audio est joint

UTF-8, quoted-printable pour les corps.

En-têtes

  • From : celui d'Asterisk (réglage FreePBX « Email From »), ou mail.from_address.
  • To : destinataires de l'e-mail d'origine.
  • Subject : sujet FreePBX, précédé de mail.subject_prefix.
  • Date, Message-ID : repris de l'original.
  • X-Asterisk-CallerID, X-Asterisk-CallerIDName : repris.
  • X-Voicemail-Transcription: ok|failed
  • X-Mailer: freepbx-voicemail-ai

Contenu du corps

  1. Titre : « Nouveau message de Nom <numéro> » à partir du CallerID.
  2. Transcription : le texte, ou « Aucune parole détectée », ou l'avertissement d'échec.
  3. Détails : le corps configuré dans FreePBX (Email Body avec ${VM_NAME}, ${VM_DUR}, ${VM_CALLERID}…), conservé tel quel.
  4. Pied : mention de transcription automatique par IA, et de la pièce jointe le cas échéant.

Test sans envoi, en conditions réelles (vraie API, utilisateur asterisk) :

sudo -u asterisk /usr/bin/php /opt/freepbx-voicemail-ai/bin/voicemail-ai \
     --dry-run --verbose < tests/fixtures/voicemail.eml

--dry-run écrit sur stdout le message MIME qui aurait été envoyé (enrichi ou brut) ; --verbose recopie les journaux sur stderr, niveau debug compris.

templates/email.{html,txt}.php
Gabarits du corps de l'e-mail.

Sécurité

  • Aucune commande n'est passée à un shell : pas d'injection possible via les en-têtes ou les noms de fichiers.
  • Le jeton d'API ne se trouve que dans config/config.php, lisible par root et le groupe asterisk seulement.
  • Les fichiers audio temporaires sont supprimés dans un bloc finally.
  • Les contenus insérés dans le gabarit HTML (transcription, appelant, détails) sont échappés.
